# 内容规范（Content Spec）

> 这是本站内容的**唯一事实标准**。提示词三件套、审校清单都以它为准。
> 你手动写内容时也请遵守。

---

## 一、目录结构

```
content/series/
└── <系列id>/              # 英文短横线，如 deepseek-harness
    ├── _meta.md           # 系列元卡（每系列必须有且仅有一个）
    └── NN-slug.md         # 章节：两位数字前缀 + 英文 slug

content/posts/
└── YYYY-MM-DD-slug.md     # 独立文章（不成系列的单篇）
```

- **章节顺序由文件名的数字前缀决定**（00、01、02……），与 frontmatter 无关；
- 系列id 和文件名只用小写英文、数字、短横线；
- `_` 开头的文件不会被当成章节。
- **独立文章**放 `content/posts/`，不需要 `_meta.md`，按日期排序。

## 二、系列元卡 frontmatter

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 系列中文名 |
| `en` | | 英文名，封面装饰用（全大写） |
| `sub` | | 一句话概括 |
| `intro` | | 长介绍，书架页展示 |
| `category` | ✅ | 分类 key：`ai` / `source` / `math` / `engineering` / `life`（在 src/site.config.ts 定义） |
| `level` | | `intro` 入门 / `core` 进阶 / `deep` 硬核 |
| `hue` / `hue2` | | 封面双色 hex，如 `"#2F6B4F"` |
| `status` | | `ongoing` 连载中 / `done` 完结 / `paused` 暂停 |
| `order` | | 书架排序权重，小的靠前 |
| `phases` | | 分卷：`[{name: 卷一·xxx, slugPrefix: "0"}]`；slugPrefix 匹配章节文件名前缀 |
| `draft` | | `true` 则整系列隐藏 |

## 三、章节 frontmatter

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 格式固定「第NN讲·标题」 |
| `summary` | ✅ | 50 字内，说明本讲解决什么问题 |
| `objectives` | ✅ | 学习目标 2~4 条，动词开头，可检验 |
| `keyPoints` | ✅ | 要点回顾 3~6 条，每条一句话（显示在章末） |
| `tags` | | 2~5 个标签 |
| `minutes` | | 手工指定阅读时长；缺省按字数估算 |
| `draft` | | `true` 则不构建该章 |

## 四、独立文章 frontmatter（content/posts/）

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 文章标题 |
| `summary` | ✅ | 一两句话概括 |
| `date` | | 发布日期，影响排序 |
| `category` | | 同系列分类 key |
| `tags` | | 2~5 个标签 |
| `minutes` | | 手工指定阅读时长 |
| `draft` | | `true` 则不发布 |

独立文章结构更自由：开篇引入 + 2~4 个二级标题即可，不必强求「试一试 / 下一讲预告」。

## 五、正文结构约定（系列章节）

1. 开篇：类比或真实场景引入，100 字内，禁止套话；
2. 正文：2~4 个二级标题（##），先结论后展开；关键概念首次出现给"一句话定义+为什么需要它"；
3. 代码块标注语言、关键行中文注释、代码后逐段解释；
4. 结尾必有：「试一试」（动手练习）和「下一讲预告」；
5. 文风：说人话、多类比但回到严谨、中英文之间空格、单讲 2500~5000 字。
