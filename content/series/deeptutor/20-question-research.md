组卷老师嘴里可以一直念叨「这道太死记、那道能考迁移」，那不等于卷子已经交到你手里。要等他说「好，题目如下」。DeepTutor 的 **deep_question（深度出题）** 和 **deep_research（深度研究）** 常用同一类礼貌：**LABEL（标签灯）**——回答第一行先报站，程序才知道这一轮算不算交卷。说明书在 `deeptutor/core/agentic/` 一带的标签协议里；第八、十一讲已经铺过直觉，这里看两门课怎么用。

## 出题课：探索、计划、一题一循环

能力入口 `deeptutor/agents/question/capability.py`，主干流水线 `deeptutor/agents/question/pipeline.py`。自定义出题大致三步：

1. **Explore（探索）**：灯是 THINK / TOOL / FINISH。交卷灯亮起的那段话，是给学生听的开场白（「我查过……接下来出 N 道」），不是最终试卷。
2. **Plan（计划）**：一盏计划灯，吐出每道题的模板清单（题型、难度、考点），通常不再乱跑工具。
3. **Quiz（逐题）**：每道模板再开一轮 THINK / TOOL / FINISH；交卷灯后的正文要是严格的题目 JSON，解析成功才弹成题卡。写歪了还有一次「只许 FINISH」的修补机会。

还可以走 **mimic（仿卷）**：从试卷 PDF 抽模板，跳过探索和计划；或 **followup（追问）**：盯着已有一题答疑，不必整张重出。教具怎么拼，和聊天共用 `tool_composition`——挂了讲义就能翻，你的网页搜索开关仍然算数。但**下课看灯，不看「这轮有没有按按钮」。**

> 小结：出题时，「说完一句完整的话」≠「卷子交了」；交卷灯才算。

## 研究课：先问清，再分块查，再写报告

能力入口 `deeptutor/agents/research/capability.py`，编排在 `ResearchPipeline`。阶段牌子是：rephrasing → decomposing → researching → reporting。

- 改写阶段可以用 **ask_user** 把题目问清楚，也可以题目已经够清楚就直接 FINISH；
- 拆成若干 **block（研究块）** 后，每块循环常见灯：THINK、TOOL、**APPEND**（发现值得单开的新分题就追加）、FINISH（交出本块带引用的小结）；
- 有工具可用时，协议要求先取证再交卷，不许空手套白狼编引用编号；
- 还支持大纲预览：先给你看分题提纲，你改完确认，再继续后面的调研与报告。

和出题一样：中间那些完整句子，可能只是草稿或旁白；**FINISH** 才把该交给下一阶段或写进报告的正文钉住。聊天那套「不按按钮就下课」在这里会太早响铃。

> 小结：研究课用灯管理「想 / 查 / 加题 / 交块」，避免半成品当报告。

## 试一试

把「再出三道选择」拆成：想题型、查材料、交卷。若中间任何一句被当成已经交给学生，缺的是哪一块？打开 `question/pipeline.py` 文件头注释，核对是不是探索→计划→逐题。再扫一眼研究提示里的 APPEND，想一个「查着查着冒出新分题」的课堂例子。
