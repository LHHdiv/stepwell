毕业不是再背一张架构图。请想象一位真实的学习者——可以是你自己——带着一句具体的问题走进你的搭建。若他走完后觉得「被教到了」，这堂毕业设计才及格。DeepTutor 仓库很大，但最小家教可以很小。

## 最小家教的四块积木

1. **会说话的模型**  
   在运行时设置里配好厂商与模型，确认 `complete` / `stream` 通（第二十五讲）。没有这一块，后面都是道具。

2. **一扇学生进得去的门**  
   任选：`deeptutor chat` / `deeptutor run chat "..."`，或 `deeptutor start` 开网页。三扇门同一位老师（第二十七讲）；先打通一扇即可。

3. **一种教法，而不是十种**  
   默认 chat 已经能检索、解释、停下来问学生。若你的毕业主题是「多一颗按钮」，加工具（第三十二讲）；若是「解题课要换下课铃」，再考虑独立能力（第三十三讲）。不要一上来并行 Book + Partner + MCP。

4. **过程可被看见**  
   终端里的阶段与工具日志，或网页气泡与痕迹。学生需要知道家教在翻讲义还是在瞎编——这是辅导产品和普通聊天框的差别（第零讲就埋过）。

可选第五块：挂一份小知识库或一份技能卡。仍然服从「先小」：一份 PDF、一个 `SKILL.md` 胜过空泛的「知识中台」。

> 小结：模型、门、一种教法、看得见的过程——四块就成立。

## 验收句式：说学生，不说海报

请把验收写成学生能点头或摇头的句子，例如：

- **听得懂**：问「用中学例子讲清方差」，回答里有生活类比，且没有把工具旁白存成最终笔记。
- **找得到**：上传的讲义被引用或检索到；关掉知识库后，不再假装翻过那本讲义。
- **停得下来**：简单寒暄不会空转二十轮；需要选公式/类比时，会出现可点的选项并在同一轮继续。
- **跑得安全**：若启用了代码，没有沙箱时会明确说不能跑，而不是在主机上裸奔（第二十六讲）。
- **不串台**（若开了多用户）：学生 B 的会话列表里看不到学生 A 的私人笔记（第三十一讲）。

反面句式尽量别写进验收：「打造智能闭环」「全面赋能个性化」——它们无法在五分钟内证伪。本课系列从一开始就避开空口号；毕业设计沿用同一标准。

建议演示路径（可录像给自己看）：

1. 冷启动：只寒暄 → 应快速短答。  
2. 正题：带讲义或明确约束的概念题 → 应出现检索或结构化讲解。  
3. 你加的那一笔：专用工具被调用，或专用模式走出正确下课条件。  
4. 故意断网 / 错 Key / 无沙箱各试一次 → 应失败得可理解。

> 小结：能摇头的句子，才是验收；不能摇头的，是文案。

## 做大之前的刹车

若四块积木已通，再按需加码：MCP 借仪器、Partner 进 IM、Book 做活书。每一加码都补一条新的学生验收，而不是只补架构箱。改内核时优先动教法所在层（循环、工具、能力），少复制入口。版本号以你仓库里 `deeptutor/__version__.py` 为准；行号会变，职责锚点不变——第零讲的读法继续有效。

> 小结：变强是加验收，不是加形容词。

## 试一试

写一张卡片，正面是你的最小家教一句话定位（例如「帮高中生把物理错题讲成类比」），背面写三条可演示的验收句。然后真实跑一遍演示路径，把失败的那一条改成「下一步只修这个」。不必发表产品，卡片贴在显示器边上即可。
