智能体拿着你 API key、能跑命令、能写文件——没有安全设计，这就是定时炸弹。dsh 的安全体系有两层：**能力接缝**（架构层）和**审批**（交互层）。

## 能力接缝：把"能做什么"抽象出来

注意 dsh 的包名：`fs`、`shell`、`sandbox`、`subprocess`——它们大多不直接实现功能，而是定义**接缝（seam）**：一组接口 + 一个本地默认实现。

```ts
// 概念示意：fs 接缝
interface FileSystemCapability {
  read(path: SafePath): Promise<Buffer>;
  write(path: SafePath, data: Buffer): Promise<void>;
  // 每个方法都只接受"已验证路径"类型
}
```

妙处在类型：`SafePath` 是第 10 讲的 Branded Type——只有通过安全检查的路径才能获得这个类型，**裸字符串根本传不进接口**。想绕过沙箱？类型系统先不答应。

接缝的意义：本地实现（直接读写磁盘）可以整体替换成沙箱实现（容器/Landlock 隔离）、远程实现（文件在服务器上）——上层工具代码一行不改。

## 审批：危险操作的人工闸门

第 22 讲的 pre-execute 瀑布，正是审批的挂载点。dsh 的策略系统定义哪些操作算"危险"（写文件、执行命令、网络请求），命中后流程暂停，UI 弹出确认框：

```
智能体想执行：rm -rf ./build
[允许一次] [本会话总是允许] [拒绝]
```

用户的选择也会被记住（会话级/永久级），下次同样操作不再打扰。**审批记录同样入日志**——谁批准的、何时批准的，可审计。

## Landlock：内核级围栏

`native/landlock-run/` 是一个 Linux 小工具，用内核的 Landlock 特性给子进程套上文件系统围栏：进程只能访问白名单目录，越界访问直接被内核拒绝——不是"程序自觉不越界"，而是**越不了**。macOS 上没有 Landlock，dsh 会退化为应用层检查（弱一些，但流程一致）。

## 安全设计的三个心得

1. **边界设在类型上**：让非法数据传不进来，而不是在函数里层层 if；
2. **默认最小权限**：先不给能力，用户批准了才放大；
3. **一切可审计**：审批和执行全进日志，出事能回溯。
