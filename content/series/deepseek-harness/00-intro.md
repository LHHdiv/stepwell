你一定用过 DeepSeek 的对话界面：输入问题，答案一个字一个字地流出来。这背后看起来只是一问一答。但如果我让你写一个程序——它不只回答问题，还能**读你的文件、执行命令、上网查资料、把任务拆成步骤自己完成**——你会发现光有模型根本不够。

模型只负责"想"。谁负责让它"看"（读取你的代码和文件）、"动"（执行命令、调用工具）、"记"（保存上下文和历史）？谁负责在它想岔了的时候踩刹车（权限审批、沙箱隔离）？负责这些的那一层软件，就叫 **Harness**。

Harness 这个词的本义是**马具**——套在马身上、让人能驾驭马的那套皮带和挽具。大模型就是那匹马力惊人的马：力气大、跑得快，但不认识路、也不懂交通规则。harness 就是让人类能安全驾驭它的那套装置。缰绳是权限控制，马鞍是会话管理，蹄铁是工具系统——而 **dsh（deepseek-harness）就是 DeepSeek 官方开源的一整套马具**。

本系列要做的，是把这套马具**逐个零件拆开、看懂、再装回去**。这是第 00 讲，我们先回答三个问题：dsh 到底是什么、为什么值得你花几十讲去精读它、这门课怎么上。

## 一、先看清对手：大模型 API 到底给了你什么

要理解 harness 的价值，得先看清它补的是什么缺口。当你调用 DeepSeek 的 API 时，你得到的其实只有一种能力：

> **输入一串 token（可理解为文字碎片），输出一串 token。仅此而已。**

没有记忆（每次请求都要把历史重新发一遍）、没有手脚（不能执行任何操作）、没有眼睛（看不到你的文件系统）、没有自律（可能编造事实、可能执行危险操作）。把这四种"没有"补齐，就是一个智能体的全部工程量：

| 缺口 | 补齐它的器官 | dsh 里对应的包 |
|---|---|---|
| 没有记忆 | 会话日志与历史管理 | `core/session`、`storage` |
| 没有手脚 | 工具定义、派发与执行 | `core/tools`、`shell`、`fs` |
| 没有眼睛 | 文件、网页、代码的读取能力 | `workspace`、`web`、`lsp` |
| 没有自律 | 权限审批、沙箱、防御性检查 | `sandbox`、`guard`、`interaction` |

而把这些器官**组装起来并让它们协同运转**的那根主轴——接收输入、组装请求、解析回复、派发工具、循环往复——叫 **Agent Loop（智能体循环）**，住在 `core/agent-loop` 包里。

这张表就是本系列的藏宝图。卷二拆第一行，卷三拆主轴，卷四拆第二、三行，卷五拆"怎么跟模型说话"，卷六到卷八拆外接设备和整机装配。你现在不需要记住这些包名，只需要记住这个印象：**每一个"没有"，都对应着一组真实的源码**。

> 💡 **知识拓展：token 是什么？**
> 大模型不认识"字"，只认识 token——把文本切分后的最小单位，可能是半个词、一个词、或一个标点。中文里一个汉字通常是 1~2 个 token。API 按 token 计费，上下文窗口也按 token 计量（比如 128K token 约等于一部中篇小说）。理解 token 对后面读"上下文压缩"（第 16 讲）至关重要：当对话太长装不进窗口时，dsh 怎么把旧内容"压缩"掉。

## 二、dsh 是什么：一句话与三个证据

打开 [deepseek-harness 的 GitHub 仓库](https://github.com/deepseek-ai/deepseek-harness)，README 第一段写着两个关键词：

> 它采用**一切皆插件**的架构，并由 **Cordis** 驱动。

先解释第一句。"一切皆插件"（Everything is a plugin）不是说它带了很多插件，而是说它的**每一个器官都是插件**：模型适配器是插件、每个工具是插件、连驱动整个智能体的主循环本身也是插件。仓库里没有任何写死的"特权内核"——你想替换任何一部分，都是往配置树里挂一个新插件，而不是改核心代码。

第二句里的 Cordis 是它底层的插件框架，以 vendor（内嵌源码）方式放进仓库的 `vendor/` 目录。你可以把 Cordis 理解成一块插线板：每个器官插上去就工作，拔下来不留痕迹。第 03 讲会专门拆这块板子。

"一切皆插件"不只是工程洁癖，它带来三个直接好处：

1. **可学习**：每个器官边界清晰、可以单独读懂，不用一次吞下整个系统；
2. **可替换**：不喜欢默认的工具审批策略？写个插件换掉它，一行核心代码都不用碰；
3. **可演进**：DeepSeek 自己迭代时也是加插件、换插件，而不是不断给核心打补丁——所以代码不会随版本腐烂。

同类产品你可能听说过：Claude Code（Anthropic 的编程智能体）、OpenAI Codex CLI，以及社区里的 pi 等。它们都是 harness，只是各家实现哲学不同。dsh 的哲学让它在众多 harness 中特别适合**学习**和**改造**——而这正是你的目标。

## 三、为什么值得花 44 讲精读它

**第一，官方出品，且文档密度罕见地高。** 仓库 `docs/` 目录下有几十篇中英双语文档：架构总览、轮次流程时序图、工具目录、事件生产消费映射、能力接缝图谱、配置目录、持久化目录……其中不少是由脚本从源码自动生成的，与代码保持同步。这意味着你阅读时永远有"官方地图"可查，本系列也会大量引用这些文档作为旁证——我们不是在孤军奋战地猜代码。

**第二，它足够完整。** 从会话日志到工具沙箱，从流式输出到上下文压缩，从 MCP 协议接入到子智能体调度，一个生产级智能体该有的器官它都有。而且它的测试策略近乎苛刻——要求源文件 100% 测试覆盖（第 41 讲细讲），这说明代码是被反复锤炼过的，不是 demo 品。读懂它，等于拿到一张智能体解剖图；以后你看任何 Agent 框架，都是在看这张图的变体。

**第三，它是 TypeScript 写的。** 相比 C++ 或 Rust，TypeScript 的类型系统会把作者的意图直接写在代码里：函数接收什么、返回什么、哪些状态不可变，类型签名本身就是微型设计文档。对零基础读者，这是最友好的工业级代码库之一。遇到生疏的语法，本系列会就地开「知识拓展」小灶，比如读到 Branded ID 时讲 TypeScript 类型体操（第 05 讲）。

**第四，终点是一个属于你的智能体。** 本系列的毕业设计（第 43 讲），是让你写出自己的插件包、组装出一个能陪你学习工作的个人超级智能体。到那时你会发现，前面 38 讲的每一个零件，都是为了让你有底气说出这句话："我知道它每一层是怎么运转的，所以我知道该怎么改它。"

## 四、这门课怎么上

本系列不是"教你怎么用 dsh"的使用手册，而是**源码精读课**。每一讲的固定结构是：

1. **心智模型**：用类比和图景先理解这一块"是什么、为什么存在"；
2. **对照源码**：打开真实文件，沿着关键类型定义和函数读下去，关键行配中文注释；
3. **知识拓展**：涉及的前置知识（TS 语法、协议、设计模式）就地补课；
4. **动手验证 / 试一试**：留一个小实验，亲手确认你的理解；
5. **要点回顾 + 下一讲预告**：三分钟复习，并交代承上启下。

你需要准备的只有两样东西：一台能安装 Node.js 的电脑，以及"遇到看不懂的语法把它当生词查"的心态。不需要提前精通 TypeScript——但需要**持续动手**：每讲的"试一试"请务必做，源码阅读是肌肉记忆，不是观光。

关于节奏：全系列九卷 44 讲。卷一是热身与地图；卷二、卷三是地基与心脏，最硬核也最重要；卷四至卷八逐个器官展开；卷九毕业实战。不必一口气按顺序读完，但**00–04 讲是后续一切的地图，建议先走完**。
