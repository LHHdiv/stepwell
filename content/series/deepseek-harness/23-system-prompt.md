"你是一个乐于助人的助手"——这句话在 dsh 里不是写死的，是**拼**出来的。`core/system-prompt` 包管理一个**段落（section）列表**，每次请求前按序拼装成完整系统提示词。

## 段落制的好处

如果系统提示词是一整块字符串，想加一条规则就得改核心代码。段落制下，每个插件可以注册自己的段落：

```
[段落1] 身份与基调（核心插件）
[段落2] 环境信息：操作系统、工作目录（环境插件）
[段落3] 工具使用守则（tools 插件）
[段落4] 安全边界：什么不许做（sandbox 插件）
[段落5] 你的人格设定（你的自定义插件！）
```

模型每次看到的系统提示词 = 这些段落的顺序拼接。**段落有优先级/顺序约定**，保证"你是谁"永远排在"注意事项"前面——顺序对模型注意力有实际影响，不是随便排的。

## 默认段落巡礼

打开 `core/system-prompt/src/index.ts`，能找到核心 bundle 注册的默认段落。值得细读的是**工具使用守则**段落：它教模型"何时该调工具、参数怎么填、结果怎么看"。模型工具用得好不好，一半靠工具的 description（第 30 讲），另一半就靠这段守则。

## 你的第一次提示词定制

基于 dsh 打造个人智能体时，你最高频的定制就是加段落：

```ts
// 你的插件里
ctx.systemPrompt.register({
  id: 'my-persona',
  position: 'after-identity',   // 插在身份段之后
  text: '你是小拾，李同学家的智能体。说话简洁，中文优先，涉及家务安排时主动确认时间。',
});
```

不用 fork、不用改源码，人格就换成了你家的。这就是第 03 讲"换部件不动核心"的又一次兑现。
