卷五收官。前面五讲都在讨论怎么和模型对话，但有一件事悬而未决：**API 密钥放哪？** 这个问题处理不好，轻则密钥泄漏进 git 仓库公之于众，重则配置文件同步到云盘全家桶泄露。`packages/credentials` 的答案从一条准则开始。

## 一、一条准则：配置携带引用，绝不携带值

README 开宗明义：

> settings 分节或 cordis.yml 条目写 `apiKeyEnv: DEEPSEEK_API_KEY`——**引用**背后的值存放在凭据提供方处。

注意这个分层：配置文件里只有一个环境变量名（引用），真正的密钥活在凭据提供方（credentials-local 提供本地托管存储）。这条准则立刻兑现三个推论：

1. **设置文档可以放心同步、放心渲染**——配置界面显示的是"已配置，来自环境变量"，不是密钥本体。截图发群里也不泄密；
2. **describe() 无需持有值就能回答三问**——"配置了吗、来自哪层、能否写入"。查询元数据不需要接触机密；
3. **轮换密钥不触碰任何配置文件**——换 key 只动提供方那一层。

这是经典的**间接化**手法：在"使用方"和"敏感资源"之间插一层可替换的中间人。Git 历史里最常见的事故就是密钥进了配置文件——引用哲学让这类事故在结构上不可能发生。

## 二、三个推论的操作细节

**按操作解析。** "resolve(ref) 在每个操作开始时调用（LLM 适配器每次模型请求解析一次），绝不跨操作缓存。"这句注释回答了一个常见疑问：为什么不像传统应用那样启动时读一次密钥存内存？因为缓存引入陈旧性问题——你换了环境变量，程序还揣着旧钥匙跑。按操作解析意味着：**改过的凭据无需重启任何插件就作用于下一次请求**。代价是每次请求多一次查找——用微小开销买运维敏捷，这买卖划算。

**空即不存在。** "空的存储值等于不存在，处处如此：resolve 跳过它，describe 报告未配置。"想象反面设计：空字符串被当成有效密钥 → 发给 API → 认证失败 → 你对着一个莫名其妙的 401 调试半小时。把空白在入口处解释为"未配置"，错误就发生在离原因最近的地方。又是 fail-loud 家族的成员。

## 三、两个键空间：一次文法设计的示范

credentials 管理两种完全不同的东西，README 用"两个键空间，两个问题"来切分：

**CredentialRef** 回答"*这个环境变量名背后是什么*"——分层的引用，可以来自进程环境、托管存储或 .env 文件，有覆盖优先级。

**CredentialKey** 回答"*某个插件为某个 id 持有什么凭据*"——比如 OAuth 授权 grant 这类**没有环境变量可读**的记录。它的键文法是：

```text
<scope>/<id>
   │     └── 具体凭据的 id
   └── 拥有该记录的【插件注册名】
```

为什么 scope 取拥有者插件名而不是"服务领域"？注释给出了一段精妙论证："grant 的 payload 以其拥有者的格式写就——否则服务同一个提供方名称的两个插件会互相读到对方的 payload，而已卸载插件留下的记录也无法与仍在使用的区分开。"翻译成白话：如果按领域命名（都叫 github/），两个不同的 GitHub 插件会共享彼此看不懂的私有数据格式，卸载残留也无法辨认。按拥有者命名后，数据隔离与生命周期管理同时解决。

最后还有一道保险："id 来自别处的消费方应先问 isCredentialKeySegment 再构造键：文法之外的 id 不可能存过记录，应读作『没有存储任何东西』，而不是在寻址上抛错。"——对**外来输入**先验证文法再当键使，把"格式错误的查询"降级为"干净的未命中"，而不是异常路径。第 `/` 分隔符同时让两种键文法互斥，两个空间永不相撞。

## 四、identity 的位置

同层的 packages/identity 处理另一维度：**智能体自己的身份**（它是谁、以什么身份对外行动）——比如子代理继承什么身份、会话归属谁。它与 credentials 的分工一句话说清：identity 管"我是谁"，credentials 管"我的钥匙在哪"。两者合起来才构成完整的对外行为主体。

> 💡 **知识拓展：十二要素应用与配置哲学**
> "配置携带引用"是云原生时代的共识——《The Twelve-Factor App》第三条就是"配置存储在环境里"。但 dsh 又比朴素的"读环境变量"前进了一步：它把"引用→值的解析"做成了**可插拔的服务接缝**（credentials-local 只是官方 Provider）。企业场景可以换成 Vault 后端、云 KMS 后端——消费方代码一字不改。老原则 + 新接缝形态，是这套代码库反复出现的组合拳。
