毕业设计（第 51 讲）动手前，先把工作区搭顺——工欲善其事。

## 工作区布局

```
~/dsh-workspace/
├── deepseek-harness/     # 官方仓库（你的 fork）
├── my-plugins/           # 你自己的插件包们
│   └── dsh-plugin-daily-quote/
└── sandbox/              # 试验场（让智能体在这里折腾，随便删）
```

插件包接入 dsh 有两种方式：放进 monorepo 的 `packages/` 下（适合深度开发），或独立目录 + 配置树挂载（适合独立演进，第 50 讲的 patch 机制）。个人智能体推荐后者——**你的插件和上游仓库零耦合，dsh 随便升级**。

## 调试回路：四拍节奏

插件开发的固定节奏，练熟它：

1. **改**：改插件代码；
2. **启**：重启 dsh（`pnpm dsh web`）——Cordis 插件在启动时挂载，没有热重载；
3. **验挂载**：`--dump-config` 确认你的插件节点出现在树上（没出现 = 注册没生效，查 inject 声明和 patch 配置）；
4. **验行为**：在对话里触发你的工具/提示词段落，观察是否符合预期。

## 三大排错手段

**一看配置树**（dump-config）：插件没生效？先看树上有没有你。没有 → 注册问题；有但行为不对 → 往下查。

**二看事件日志**：会话 JSONL 文件（第 15 讲）里每一步事件俱全。工具没被调用？看日志里模型到底发了什么 tool_use、参数是什么——**日志是智能体的黑匣子**。

**三用最小复现**：行为诡异时，把场景缩到最小——最短的提示词、最少的插件（临时注释掉 patch 里的其他插件）。90% 的"灵异事件"在最小复现里现出原形：通常是两个插件的提示词段落打架，或工具 description 误导了模型。

## 试一试

把工作区建起来，跑通四拍节奏的空转版（不改任何代码，走一遍 启动→dump→对话→看日志）。熟悉节奏后，下一讲正式动工毕业设计。
