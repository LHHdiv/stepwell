第 30 讲学了怎么定义工具，这一讲看官方的示范作业。dsh 的内置工具不在 core/tools 里，而是分布在 `packages/fs/`、`packages/shell/`、`packages/sandbox/` 等独立包——**每个工具（或工具族）是一个插件**。

## 工具清单速览

| 工具族 | 包 | 能力 |
|---|---|---|
| 文件读取/写入/补丁 | fs | 读文件、写文件、精准替换 |
| 目录列举/搜索 | fs | 列目录、glob、全文检索 |
| 命令执行 | shell + subprocess | 跑 shell 命令、管理进程 |
| 沙箱执行 | sandbox + code-runtime | 隔离环境里跑代码 |
| 终端会话 | terminal | 持久化交互式终端 |

## 精读一个：文件读取工具

以读文件为例，一个生产级工具要处理多少事：

1. **参数校验**：路径必须存在、必须在允许的根目录内（安全边界！）；
2. **大小保护**：10MB 的文件不能整个塞给模型——截断并告知"已截断，共 N 行"；
3. **二进制识别**：图片返回图片块，二进制返回"这是二进制文件"而不是乱码；
4. **结果格式**：带行号返回，方便模型在后续对话里精确引用"第 42 行"；
5. **失败诚实**：文件不存在就明确报错，绝不返回编造的内容。

注意第 2 和第 5 点：**工具是模型与真实世界的边界，边界上必须设防，且必须诚实**。模型对世界的全部认知来自工具结果——工具撒谎（返回截断却不说明），模型的推理就从根上歪了。

## 好工具的四个标准

读完几个内置工具后可以总结出官方口味：

1. **描述精准**：description 说清"是什么+何时用"，甚至说"何时不要用我"；
2. **参数克制**：参数尽量少、尽量简单。每个多余参数都是模型的出错机会；
3. **结果干净**：返回模型需要的，过滤它不需要的（噪音浪费上下文）；
4. **失败诚实**：报错信息说人话、给线索，让模型能自我纠正。

你以后写自己的工具（查天气、控制智能家居、查快递），照这四条打磨，模型用起来就顺手。
