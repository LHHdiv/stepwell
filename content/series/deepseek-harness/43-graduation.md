终章。四十三讲的旅程走到了出口——而这个出口同时是一扇门：从这一讲起，dsh 对你不再是"学习的对象"，而是"手中的材料"。毕业设计的题目只有一句话：**基于 dsh 打造一个你每天真的会用的个人智能体**。

## 一、需求先行：三个灵魂拷问

动手写代码之前，先回答：

1. **它替你解决什么高频痛点？** 日报整理、代码审查助手、家庭知识库管家、学习陪练……选一个你每周至少要做三次的事。"什么都能干"的智能体等于什么都干不好；
2. **它需要哪些感官？** 对照第 01 讲的五大族群勾选：要读文件吗（fs）？要上网吗（web 家族）？要定时干活吗（schedule）？要连外部工具吗（MCP）？清单越短越好；
3. **它的边界在哪？** 哪些操作必须人工审批（第 21 讲）？哪些目录绝对不许碰（沙箱模式）？安全设计不是最后补的补丁。

## 二、架构蓝图：一个最小而完整的插件包

```text
my-agent/
├── package.json            # dsh.bundle 字段指向 patch 文件（组合包形态）
├── cordis.patch.yml        # 挂载声明：我的服务、我的工具、引用的官方能力
├── src/
│   ├── index.ts            # 插件入口：inject + apply + effect 注册
│   ├── tools/              # 你的专属工具（defineTool 契约，第 18 讲）
│   └── prompts.ts          # 提示词片段（system-prompt 的 section 注册，第 15 讲）
└── tests/
    ├── hmr.spec.ts         # 注册表 dispose 安全测试（第 41 讲的范式）
    └── smoke.e2e.ts        # 带密钥冒烟测试
```

配套一份叶节点 YAML（第 42 讲）：加载官方 dsh-base 组合包打底，叠上你的 bundle，patch 掉想替换的部分。**核心最小化、能力走扩展点、配置分三层**——这三句话是全系列架构观的总纲。

## 三、三阶段实施路线

**阶段一：主干通（第一周）。** 目标只有一条：你的叶节点配置能启动，模型用你写的 system prompt 说第一句话。验收：dump-config 里能看到你的段落注册。此阶段刻意不写任何工具——先确认装配链路通，再谈功能。

**阶段二：器官齐（第二到三周）。** 按 MVP 需求逐个加能力：一个 defineTool 工具（照 cookbook 的 adding-a-tool 走）、必要的审批规则（pre-execute 监听者）、如果需要定时则上 schedule。每加一个器官立刻配两样东西：一条日志验证 + 一个 HMR 测试。**能力和测试同生共死，不许赊账。**

**阶段三：磨光亮（第四周起，无限期）。** 打磨提示词片段的措辞（工具描述是写给模型的提示词！）、给大输出接 spill 策略、把配置从硬编码迁进 settings namespace、写一份属于你项目的 README。这一阶段没有终点——智能体会随你的需求生长。

## 四、毕业标准

满足以下全部条件，即为本系列合格毕业生：

- [ ] 你的智能体在真实场景连续使用超过一周；
- [ ] 至少一个自定义工具通过审批流被真实调用过；
- [ ] 经历过一次进程重启/断电，会话无损恢复（仅追加日志的实战检验）；
- [ ] 有一次"行为不符预期"，你靠 dump-config 和日志定位到了根因；
- [ ] （选修）向官方提过一个 PR——哪怕只是修文档。

注意第一条和最后一条：**能演示不算数，天天在用才算数**；消费开源世界的最好方式是回馈一行代码。

## 五、告别：你现在的位置

回望第 00 讲那个问题："当我们说 AI 智能体的时候，工程上到底需要哪些零件？"现在你能给出完整的答案：一条仅追加的会话日志作为唯一事实源（卷二）；一个五动词接口驱动的循环作为心脏（卷三）；一套带流水线与双保险的工具系统作手脚（卷四）；一层带协议洁癖的模型适配作嘴耳（卷五）；MCP/LSP/ACP/subagent 作外联（卷六）；hooks/skill/jobs 作高阶神经（卷七）；boot 到 sdk 的产品化包装作皮肤骨骼(卷八)；以及让这一切持续可靠的测试文化（卷九）。

但比答案更值钱的是你获得的三种眼光：**读源码时先找不变量**；**做设计时先问扩展点归属**；**遇故障时先看日志事实**。这三种眼光不依附于 dsh——换任何一个框架、任何一代模型，它们依然有效。

马具已经卸下又装好。骑上你的马，出发吧。
