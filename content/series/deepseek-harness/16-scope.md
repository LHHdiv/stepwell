卷二最后一讲，回到一个看似不起眼、实则无处不在的问题：**当系统里同时跑着十个智能体时，工具注册表、事件监听器这些东西，是大家共享一份，还是各用各的？**

全共享会串台（A 智能体的私有工具 B 也能调）；全隔离又浪费（公共工具得复制十份）。dsh 的答案是 `core/scope` 包——官方架构文档称它为"按 agent 划分作用域的注册原语"。注意措辞：它是**原语（primitive）**，一个纯库，连 ctx 键都没有。别的包拿它当积木搭出自己的作用域机制。

## 一、ScopeKey：故意的"不透明"

先看核心类型：

```ts
/** 一个不透明的、按身份比较的作用域键。 */
export type ScopeKey = object
```

就这一行，但每个词都是决定：

- **`object` 而非 `string`**：字符串可以伪造、可以拼错、可以撞车；对象按**引用身份**比较——`===` 相等当且仅当是同一个对象。想造一个新作用域？`{}` 一下就有了，全球唯一，无需中心化发号。第 10 讲的 Branded ID 解决的是"字符串别混淆"，这里更进一步——干脆不给字符串机会；
- **不透明（opaque）**：类型上你拿不到它的任何属性。作用域键就是作用域键，除了交给 scope 系统比对，没有任何别的用途。

配套的关系存储也讲究：

```ts
const carrierKeys = new WeakMap<object, ScopeKey | undefined>()
const scopeParents = new WeakMap<ScopeKey, ScopeKey>()
```

两个 WeakMap：键不被强引用，作用域对象没人用了就被垃圾回收自动收走，连同它在 map 里的记录。**作用域的生命周期管理是零成本的**——这是"原语级代码"的自我修养：不给自己也不给使用者留清理负担。

> 💡 **知识拓展：WeakMap 为什么能做到这一点？**
> 普通 Map 持有键的强引用——只要 Map 活着，键就永远不能被回收，用久了就是内存泄漏。WeakMap 对键只保留"弱引用"：不妨碍垃圾回收，一旦键在别处再无引用，条目自动蒸发。它因此不支持遍历（条目说没就没），但作为"给对象挂元数据"的隐藏侧表堪称完美。dsh 里到处是 WeakMap——凡是"附属于某个对象的内部状态"，都用这个姿势存。

## 二、两条方向相反的规则

scope 的行为规则一共两条，方向相反，合起来构成完整的权限拓扑。源码注释原文：

> 注册视图沿链**向下**继承（子作用域看得见祖先的层）；事件准入沿链**向上**扩展（挂在祖先上的监听器能收到派发给后代键的事件）。

画成图更直观：

```text
        [根 scope]          ← 公共工具注册在这里
        ↙ 注册可见 ↓      ↑ 事件可达
    [agent-A scope]
      ↙              ↑
[agent-A 子代理]   ← 它能看到根和 A 的全部注册；
                      根上监听器也能收到它的事件
```

- **向下继承注册**：孩子的世界里包含祖先的一切积累。主智能体注册的工具、提示词片段，子代理天然可用——不用重新声明一遍公共设施；
- **向上扩展事件**：祖先的监听器覆盖后代。你在根上挂一个"审计所有工具调用"的监听器，无论哪个后代 agent 触发了调用，都逃不过你的耳朵。

这两条合起来，恰好实现了官方架构文档里那句话："让某个会话拥有不同的能力集合 → 组装一个 agent preset；其中的服务行需要 isolate realm"。**隔离是加法不是减法**：默认继承全部，需要差异化时在中间插一层自己的注册即可。

## 三、改父链接：带刹车的能力

作用域的父子关系不是终身制。源码提供了显式的改绑接口：

```ts
export interface ScopeParentBinding {
  /**
   * 把绑定的键改挂到另一个父级……仅在旧父级下没有任何被持有的产出时有效
   * ——空白会话重组契约，由持有者维护。
   */
  rebind(parent: ScopeKey): void
}
```

两个刹车值得细看：

**① 环检测。** 内部的 `linkScopeParent` 在建立链接前沿着候选父级的父链一路爬到顶，发现链条上有自己就抛错："scope parent link would form a cycle"。没有这个检查，A→B→A 的环会让各种沿链遍历死循环。第 14 讲 traceSession 拒绝血缘环、这里拒绝作用域环——**凡是允许用户定义"指向关系"的地方，都要防环**，这已经是 dsh 的肌肉记忆。

**② 重组契约。** rebind 不是随时随地的魔法：注释要求此刻旧父级下的产出没有被任何人持有。原因不难想——注册视图是从父链实时推导的，如果某个已经分发出去的注册项还引用着旧父层的产物，改绑瞬间它们就成了"无源之水"。所以契约把责任交给持有者：先清场，再搬家。**能力越灵活的操作，前置条件越严格**。

## 四、Scoped<T>：路由专用的事件信封

scope 包还提供一个精巧的类型：

```ts
export type Scoped<T extends object> = object & { readonly [ScopedBrand]: T }
```

眼熟吗？这是第 10 讲品牌类型的变体！但它品牌的不是 ID 字符串，而是**事件载体本身**。用途：把事件派发给"某个特定作用域"的监听器时，用 Scoped 包装过的载体做路由——监听器声明接收哪类主体的事件，编译期就能查错（type parameter 记录主体类型供派发检查），而载体本身不暴露主体的任何属性，真正的主体只在事件载荷里出现。**路由信息与业务数据分离**，监听器想偷看路由对象的内容？类型系统不允许。
