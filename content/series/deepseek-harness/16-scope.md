卷二收官。最后读一个"小而关键"的包：`core/scope`。它小到没有依赖、几十行代码，却是第 30 讲"作用域化工具注册表"的地基。

## 问题：全局注册表的污染

想象工具注册表是一个全局 Map。你起了一个子智能体做代码审查，不希望它有写文件的工具。怎么办？在 execute 里加判断？"如果是子智能体就拒绝写文件"——每个工具都要写这种 if，灾难。

scope 的思路：**注册表不是全局的，而是挂在各自的"世界"（scope）里**。主智能体有主世界，子智能体有子世界；子世界可以继承父世界的部分内容，也可以完全另起炉灶。工具查找只在"本世界"进行——子智能体根本看不见写文件工具，无需任何特判。

## 数据结构：树

scope 组织成一棵树：根是全局世界，每个 agent 是一个节点。查找规则（概念示意）：

```
lookup(agentScope, key):
  if key in agentScope.own:      return agentScope.own[key]   # 自己有，用自己的
  if agentScope.parent:          return lookup(parent, key)   # 没有就问父亲
  return undefined                                            # 根都没有，真没有
```

沿父链向上的查找 + 本地优先的覆盖，就是"继承 + 定制"的语义。子智能体想覆盖父世界的某个工具？在自己的 scope 里注册同名工具即可——**覆盖即定制**，插件系统里极其好用的手法。

## 为什么单独成一个包

因为它足够通用：工具注册表（第 30 讲）用它、每个 agent 的局部状态用它、将来你做多智能体协作时的隔离也用它。**把最基础的机制独立成最小依赖的包**，让任何模块都能安全复用——这是 dsh 仓库组织上的一个鲜明风格（类似的还有 util/brand）。
