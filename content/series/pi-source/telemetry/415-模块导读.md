路径：`packages/telemetry/`  
npm 名：`@earendil-works/pi-telemetry`  
版本：`0.85.1`（与 coding-agent 锁在一起）

## 这个包是什么

**厂商无关的观测契约**，不是 OpenTelemetry SDK，也不是 Sentry 适配器。它只保证：

1. 一份显式传递的 `TelemetryContext` / `TelemetrySpan`（回调管生命周期，没有 `end()`）
2. 共享的 `NOOP_TELEMETRY_CONTEXT`（关掉观测时仍走同一套 API）
3. 进程内参考实现 `InMemoryTelemetryContext`（测试、本地诊断）
4. `defineTelemetrySchema` + `createTypedSpanStarter`：用 JSON 可序列化的 schema 推出精确 TypeScript 类型
5. `@earendil-works/pi-telemetry/testing`：适配器一致性套件，任何测试框架都能跑

它**不**导出 exporter、不持有全局 current-span、不依赖某家后端。业务包把 context 当参数往下传；真正写到 OTel / Sentry / 日志的是应用自己的 adapter。

## 在执行链的哪一段

现行 `./pi-test.sh` 交互 / print **不 import 本包**。

```text
./pi-test.sh -p --no-session "你好"
  → experimental/cli.ts → main → createAgentSession
  → Agent.prompt → agent-loop → streamFn → pi-ai
```

这条主链走的是 `packages/agent` 的 `Agent` + `agent-loop`，**不是** `harness/`。`agent.ts` / `agent-loop.ts` 里没有 `telemetryContext`。`packages/ai` 的请求 options 有可选字段 `telemetryContext?`，coding-agent 的 SDK 没有填，所以厂家 HTTP 也不会开 span。

本包真正被 import 的位置：

| 谁 | 干什么 |
|---|---|
| `packages/agent/src/harness/context.ts` | `getTelemetryContext` 默认落到 `NOOP_TELEMETRY_CONTEXT`；`withTelemetryContext` 把父 span 挂到 Chord `Context` |
| `packages/agent/src/harness/telemetry.ts` | 拥有 `AI_TELEMETRY_SCHEMA` / `HARNESS_TELEMETRY_SCHEMA`，用 `createTypedSpanStarter` 包一层 |
| `packages/ai/src/types.ts` | 请求 options 接受 `TelemetryContext`，自己**不**定义 schema |
| 实验 server/client | 不经过本包。远程会话走 protocol/client/server |

结论：主链 print / 交互 **走不到** 这里。Agent Harness 路径（可恢复运行时、实验 Session worker）会走到，但默认是 noop，业务回调照跑、不记任何 span。要看见记录，必须显式注入 `InMemoryTelemetryContext` 或自己的 adapter。

## 依赖谁

`packages/telemetry/package.json` 的 `dependencies` 是空的。runtime-neutral：不碰 `AsyncLocalStorage`、不碰 Node 专用 API。根入口可以进浏览器 / worker。

`./testing` 子路径用 `node:assert/strict`，所以一致性套件只适合 Node 测试。

被谁依赖：

- `@earendil-works/pi-agent-core`（re-export 契约 + 拥有 pi 域 schema）
- `@earendil-works/pi-ai`（options 透传）

## 契约要点（读文件前先记住）

- **没有 public `end()`。** `startSpan(options, callback)` 拥有结算：callback 返回值 / Promise settle 才关 span。
- **同步准入、只调一次。** 业务 callback 必须同步被调用；adapter 失败不得吞掉业务、也不得让业务跑两遍。
- **记录是被动的。** `setAttributes` / `addEvent` / `setStatus` 不抛；读属性失败整次调用原子丢弃。
- **显式 status 覆盖自动 status。** 正常完成默认 `ok`，抛错默认 `error`；若 callback 里已经 `setStatus`，后面的 throw 不再改写。
- **schema 只服务类型。** `defineTelemetrySchema` 是 typed identity；`createTypedSpanStarter` 运行时不校验名字、不强制 parent 规则。
