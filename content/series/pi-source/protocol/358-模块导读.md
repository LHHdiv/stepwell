协议版本常量：`PROTOCOL_VERSION = 8`

## 这个包是什么

实验 Pi 远程会话的 **字节协议**：长度前缀帧 + 一份严格 CBOR 子集 + TypeBox 信封。它不管 Unix socket 怎么连、不管 Chord 服务目录里有哪些 member。

一句话分层：

| 层 | 本包文件 | 干什么 |
|---|---|---|
| 字节流切帧 | `framing.ts` | 4 字节大端长度 + payload |
| CBOR | `cbor/*` | 把 JS 值编成一条 definite-length item |
| 信封 schema | `protocol.ts` | hello / request / cancel / response / service_update / attachment |
| 校验 + 编解码 | `codec.ts` | schema + `isJsonValue` + 帧 |

Chord 拥有信封 **里面** 的 `{ serviceId, instance?, member, args }`、`$chord.service` 控制词、订阅 snapshot/update。本包只要求那块 payload 是 strict JSON，不解析它。

## 在执行链的哪一段

现行 `./pi-test.sh` 交互 / print **走不到** 本包。

```text
./pi-test.sh                 # 无 PI_EXPERIMENTAL
  experimental/cli.ts
    runExperimentalCommand → false
    await main(args)         # 本地 AgentSession，JSONL 会话
```

只有开发旁路才进来：

```text
PI_EXPERIMENTAL=1 ./pi-test.sh server
  experimental/commands.ts
    startForegroundServer
      createUnixServer(...)                 【server 包】
        encodeServerMessage / ClientMessageDecoder   【本包】

PI_EXPERIMENTAL=1 ./pi-test.sh client
  Client.connect({ transportFactory: createUnixTransportFactory(...) })
    encodeClientMessage({ type: "hello", version: 8 })
    ServerMessageDecoder.push(chunk)
```

官方安装的 `pi` 命令 **没有** `server` / `client` 子命令（`experimental/commands.ts` 不打进 bundle）。npm 上的 coding-agent 把 `pi-protocol` / `pi-client` / `pi-server` 当 developmentDependency。

## 依赖谁

- `@earendil-works/chord`：`JsonValue` / `isJsonValue`（strict JSON 边界）
- `typebox`：信封 schema 与 `Check`

被谁依赖：`pi-client`、`pi-server`。coding-agent 实验代码从这两个包间接用到本包，也直接 `import { isServerId, PROTOCOL_VERSION }`。

## 三包串起来（先建立脑内模型）

```text
Client.connect
  transportFactory(handlers)          【client/unix：连 .sock】
  encodeClientMessage(hello)          【本包 codec → framing】
  socket.send(4-byte length + CBOR)

UnixListener.acceptSocket             【server/unix】
  Server.accept → ClientMessageDecoder.push
  finishHandshake → encodeServerMessage(hello{ serverId })

之后每一帧：
  客户端 encodeClientMessage({ type: "request", id, target, call })
  服务端 parseServiceCall(call)        【chord，本包不看】
  服务端 encodeServerMessage({ type: "response", ... })
         或 { type: "service_update", ... }
         或 { type: "attachment", attachment }
```

`target` 分两种：`{ serverId }` 是服务器级调用（attach/detach/目录）；`{ serverId, sessionId, attachmentId }` 是某次展示附件上的 Session 调用。attachmentId 由 server 生成，经 out-of-band `attachment` 消息发给客户端，**不**出现在业务 attach() 的返回值里。
