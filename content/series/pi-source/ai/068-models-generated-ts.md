源码：`packages/ai/src/models.generated.ts`  
生成命令：`npm run generate-models`（`scripts/generate-models.ts`）  
被谁调用：`providers/all.ts`（本课表不写）把它和各厂家工厂焊在一起；compat 的 `getModel` 最终读到这里。

## 本课目标

知道这文件**不能手改**、它不包含模型字段本身、只把各 `*.models.ts` 收成一张 `MODELS` 表。改价格或加模型去 `scripts/model-data.ts` / 厂家 json，再生成。

## 在系统中的位置

```text
providers/data/anthropic.json 等
  → scripts/generate-models.ts --strict
      → providers/anthropic.models.ts   （真正的 Model 对象）
      → models.generated.ts             （本文件：索引）
```

`package.json` 的 `build` 先 `generate-models` 再 `tsgo`。`check:model-data` 在离线 build 里再验一遍。

## 文件结构

文件头：

```ts
// This file is auto-generated by scripts/generate-models.ts
// Do not edit manually - run 'npm run generate-models' to update
```

然后对每个内置厂家 `import { X_MODELS } from "./providers/x.models.ts"`。

导出：

```ts
export const MODELS: {
  readonly "amazon-bedrock": typeof AMAZON_BEDROCK_MODELS;
  readonly "anthropic": typeof ANTHROPIC_MODELS;
  ...
} = {
  "amazon-bedrock": AMAZON_BEDROCK_MODELS,
  "anthropic": ANTHROPIC_MODELS,
  ...
};
```

键的集合就是 `KnownProvider` 里出现在生成目录中的那些（radius 等纯动态厂家不在这张表）。

`typeof ANTHROPIC_MODELS` 保留了上一课的 catalog 类型，所以 `MODELS.anthropic["claude-opus-4-7"]` 仍是精确 `Model<"anthropic-messages">`。

## 和图像目录的关系

聊天模型走本文件。图像模型走 `image-models.generated.ts`，生成器是另一个脚本。不要把 FLUX 写进聊天 json。

## 失败与边界

手改会被下一次 generate 覆盖。`--strict` 模式下数据对不上 schema 生成器直接退出，build 失败。新增厂家要同时改生成器的厂家列表、`KnownProvider`、以及 `providers/<id>.ts` 工厂——只改本文件不够。
