## 这个包是什么

统一的「给大模型打电话」层。Agent 循环只认识：

```ts
streamFn(model, context, options) → AssistantMessageEventStream
```

各家 HTTP 字段、鉴权头、工具 JSON 的形状、SSE 事件名，全部挡在本包。上游拿到的永远是同一套事件：`start` / `text_*` / `thinking_*` / `toolcall_*` / `done` | `error`。

coding-agent 在 `sdk.ts` 里注入的是 `modelRuntime.streamSimple`。`ModelRuntime` 实现 `Models` 接口，底层就是本包的 `createModels()` + `createProvider()` + `src/api/*.ts`。兼容旧调用方的全局 `streamSimple` 在 `compat.ts`。

本包**不**认识 Agent、工具执行、会话 JSONL。它只负责：拿 `Model + Context + Options`，发出 HTTP/WS，把厂家字节译回 `AssistantMessage`。

## 执行链走到这里时

```text
agent-loop streamAssistantResponse
  streamFn(model, { systemPrompt, messages, tools }, options)
    → coding-agent sdk.ts 包一层 timeout / retry / transformHeaders
    → ModelRuntime.streamSimple          （coding-agent，实现 Models）
         lazyStream
           applyAuth / getAuth           （auth/resolve.ts）
           provider.streamSimple         （createProvider 按 model.api 分发）
             api/*.ts streamSimple       （SimpleStreamOptions → 厂家选项）
               api/*.ts stream           （组 payload、发请求）
                 SSE / SDK chunk
                   统一事件：start / text_* / thinking_* / toolcall_* / done|error
    → for await 事件回到 agent-loop
```

有两条入口，**分发键都是 `model.api`，不是厂家商号**：

| 入口 | 谁用 | 怎么分发 |
|---|---|---|
| `Models.streamSimple` / `createProvider` | 新产品（coding-agent ModelRuntime） | Provider 持有 `api: ProviderStreams \| Record<api, ProviderStreams>`，按 `model.api` 取实现 |
| `compat.streamSimple` | 旧 import、测试、扩展里的 llama provider | 全局 `apiProviderRegistry`，`registerBuiltInApiProviders()` 把 10 个 lazy API 注册进去 |

同一厂家可以挂两种 api：OpenAI 官方既有 `openai-completions` 也有 `openai-responses`。读循环时先看 `model.api`，再打开 `src/api/` 下对应文件。

## 包的公开表面（exports）

`package.json` 故意拆成几条路，避免「import 一下就把所有厂家 SDK 拉进 bundle」：

| 入口 | 副作用 | 里面有什么 |
|---|---|---|
| `@earendil-works/pi-ai` | 无 | 类型、`createModels`、auth 接口、部分 utils。**没有** `streamSimple` |
| `@earendil-works/pi-ai/compat` | 有：注册 builtin API、加载生成目录 | 旧全局 `stream` / `streamSimple` / `getModel` |
| `@earendil-works/pi-ai/api/*` | 按需 | 一种协议一份实现 |
| `@earendil-works/pi-ai/providers/*` | 按需 | 厂家工厂。精读在 [providers/](/series/pi-source/ai/142-all-ts/) |
| `@earendil-works/pi-ai/oauth` | 无 | 扩展用的旧 OAuth 类型 |
| `@earendil-works/pi-ai/bedrock-provider` | 无 | Bun 二进制把 Bedrock 静态焊上 |
| `@earendil-works/pi-ai/bun-oauth` | 调用时 | Bun 二进制把 OAuth 流程静态焊上 |

`sideEffects` 只标了 `compat.js`、`images.js`、`providers/images/register-builtins.js`。主入口 `index.ts` 注释写死：core only, side-effect free。

## 目录怎么用

不要按字母去读 80 个 provider JSON。执行链第一次打电话时，按这张课表走：

1. 先认合约：`types.ts` 的 `Model` / `Context` / `AssistantMessageEvent`
2. 再认分发：`compat.ts` 的全局 `streamSimple`，对照 `models.ts` 的 `createProvider` 分发
3. 再认懒加载：`api/lazy.ts` 如何让 stream 同步返回、setup 失败变成 `error` 事件
4. 再认中性选项：`api/simple-options.ts` 把 `reasoning` / `maxTokens` 变成厂家字段
5. 打开你正在用的那一家 `src/api/*.ts`，只跟两件事：tools 怎么写成厂家 JSON、SSE 怎么译回统一事件
6. 鉴权出问题时再进 `auth/`
7. 事件队列、重试、溢出检测在 `utils/`
