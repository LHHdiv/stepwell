## 这个包是什么

实验 Pi 服务协议的 **传输无关客户端**。它：

- 用 `ByteTransportFactory` 换一条已认证、保序的字节连接
- 发 hello，核对对端 `serverId`
- 按 `id` 把 request/response 对上
- 把 Chord 的 subscribe 流解码成 snapshot + 有序 update
- **不**重连、**不**重放、**不**构造 typed 服务代理

typed API（Session 目录、Transcript、模型列表）是应用用 Chord binding + `createClientServiceTransport` 自己焊的。本包只提供 `request()` 和 `subscribeService()`。

Unix 传输在子路径 `@earendil-works/pi-client/unix`。

## 在执行链的哪一段

现行 `./pi-test.sh` 交互 / print **走不到**。

```text
PI_EXPERIMENTAL=1 ./pi-test.sh client
  experimental/cli.ts → runExperimentalCommand
    runClient / runClientTui
      Client.connect({
        serverId,
        transportFactory: createUnixTransportFactory({ path })
      })                         ← 本包
        Connection.connect
          encodeClientMessage(hello)     【protocol】
          等 ServerHello
      client.request({ serverId }, attachCall)
      onAttachmentChange → 之后用 SessionTarget 调 Session 服务
```

`coding-agent/src/experimental/client-runtime.ts` 对发现到的每条 Unix 路由调一次 `Client.connect`。Radius 传输是另一份 factory，仍进同一个 `Client`。

## 依赖谁

- `@earendil-works/pi-protocol`：帧、信封、decoder
- `@earendil-works/chord`：`parseServiceCall`、catalogue / subscribe 控制调用、`createServiceStateDecoder`

不依赖 `pi-server`、不依赖 `pi-agent-core`。客户端进程甚至不必和服务器同仓库版本，只要 PROTOCOL_VERSION 一致。

## 和 protocol / server 的接头

```text
framing → codec.encodeClientMessage
  Client.connect
    Connection 状态机：disconnected → connecting → connected
      第一帧必须是 server hello，且 serverId 对得上
    Client.request / subscribeService
      之后的 response / service_update / attachment

对端：
  ServerListener.start(accept)
    Server.accept → ClientMessageDecoder
    finishHandshake → encodeServerMessage(hello)
    SessionRouter 在 attach 后 publishAttachment
```

断线后 pending request 本地 reject；对端已准入的工作可能仍跑完。live attachment 被清掉。调用方必须 `reconnect()`（其实就是再 `connect()`）再 attach，只重复安全的操作。
