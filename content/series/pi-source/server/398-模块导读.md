## 这个包是什么

实验本地服务器：**路由 + 握手 + 附件生命周期**。它不实现「列 Session」「跑 Agent」这些业务。应用必须提供：

- `RoutedServerServiceHost`：连接级服务器服务（典型：`pi.session-management` 的 attach/detach）
- `resolveSession` / `openSession`：按 id 找到元数据、在本进程打开 `RoutedSessionHandle`

真正的 `Session` 和 `AgentHarness` 留在 worker 里，不进这条协议。server 把 opaque Chord 调用转到已经 attach 的那条 Session 附件。

三个 export 条件：

| 路径 | 内容 |
|---|---|
| `@earendil-works/pi-server` | `Server`、错误、类型、`ServerListener` |
| `@earendil-works/pi-server/unix` | `createUnixServer`、`createUnixListener`、`getUnixSocketPath` |
| `@earendil-works/pi-server/testing` | 协议测试用假 host、假 client、确定性 serverId |

## 在执行链的哪一段

现行 `./pi-test.sh` 交互 / print **走不到**。

```text
PI_EXPERIMENTAL=1 ./pi-test.sh server
  startForegroundServer
    createUnixServer(host, { serverId, path: getUnixSocketPath(...) })
      new Server(host, { listeners: [UnixListener] })
      server.start()
        listener.start(accept)
          每个 socket → Server.accept → handshake → SessionRouter
```

实验 server 的 Session 仓库目前是 `JsonlSessionRepo`（coding-agent `experimental/server.ts`），**不是** sqlite-node。本包不绑定任何存储后端。

## 依赖谁

- `@earendil-works/pi-protocol`：编解码、版本
- `@earendil-works/chord`：`parseServiceCall`、service control、state encoder
- `@earendil-works/pi-agent-core`：`Context`、`SessionMetadata`、`BACKGROUND_CONTEXT` / `TODO_CONTEXT`

不依赖 `pi-client`。测试子路径自己写了一个 `ProtocolTestClient` 打裸帧。

## 和 protocol / client 的接头

```text
Client.connect
  hello 帧
UnixListener.acceptSocket
  Server.accept 交给 ByteConnectionHandler
    ClientMessageDecoder.push
    finishHandshake
      host.serverServices.attachClient(presentation)
      encodeServerMessage({ type: "hello", version: 8, serverId })
    request
      target 无 sessionId → serverServices.invokeService
      target 有 sessionId → SessionRouter.executeServiceCall
        必须已 attach 且 attachmentId 对得上
      attach 成功 → 出站 { type: "attachment", attachment: SessionTarget }
```

读本包时把 Chord 当「对 call JSON 的 parser」。server 不 load facet 契约。
