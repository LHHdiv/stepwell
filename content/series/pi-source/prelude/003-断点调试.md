## 0. 只做一次的准备

```bash
cd /Users/lijunkai/Project/pi
npm install --ignore-scripts
./pi-test.sh --version
```

期望打印当前包版本（如 `0.85.1`）。`pi-test.sh` 可在任意目录调用，Pi 仍使用**你当前终端的工作目录**当项目 cwd。

`./pi-test.sh` 用 tsx 跑 `src/experimental/cli.ts`，不经过 `npm run build`。不要用全局 `pi` 跟源码行号。

## 1. 先不要开 TUI：用 --help 验证断点

交互界面会占满终端，和调试器抢屏幕。第一次跟路径用不会画 TUI 的命令。

仓库里 `.vscode/launch.json`（该目录被 gitignore，只在本机生效）已有三条配置。

1. 用编辑器打开文件夹 `/Users/lijunkai/Project/pi`（必须是仓库根）。
2. 打开 `packages/coding-agent/src/main.ts`，在 `export async function main` 左边点红点。
3. 再在 `resolveAppMode` 第一行点一个红点。
4. Run and Debug，选 **「Pi 源码：--help（验证断点）」**，F5。
5. 应停在 `main`。Call Stack 应是 `experimental/cli.ts` → `main`。`args` 是 `["--help"]`。

**不要把断点只打在 `src/cli.ts`。** 那条启动路径不会加载它。

命令行等价：

```bash
cd /Users/lijunkai/Project/pi
node --inspect-brk --import tsx packages/coding-agent/src/experimental/cli.ts --help
```

出现 `Debugger listening on ws://127.0.0.1:9229/...` 后，用编辑器 attach，或 Chrome `chrome://inspect`。

## 2. 推荐：print 模式跟「一句话」

F5 选 **「Pi 源码：print 模式（推荐跟执行路径）」**。等价于：

```bash
./pi-test.sh -p --no-session "只回复一个字：好"
```

建议沿路下的断点（点红点，不要改代码塞 `debugger;`）：

| 顺序 | 文件 | 搜什么 |
|---|---|---|
| 1 | `src/experimental/cli.ts` | `await main(args)` |
| 2 | `src/main.ts` | `export async function main` |
| 3 | `src/main.ts` | `function resolveAppMode` |
| 4 | `src/main.ts` | `const runtime = await createAgentSessionRuntime` |
| 5 | `src/main.ts` | `runPrintMode` |
| 6 | `src/core/agent-session.ts` | `async prompt(` |
| 7 | `packages/agent/src/agent.ts` | `async prompt(` |
| 8 | `packages/agent/src/agent-loop.ts` | `async function runLoop` |

没登录会在 `prompt` 的鉴权处停下，那也是有效路径。只想看启动：继续用 `--help` / `--version`。

## 3. 交互 TUI（可选）

配置名 **「Pi 源码：交互 TUI」**。`console` 必须是 `integratedTerminal`。

断点命中时 TUI 会冻住，继续运行后才刷新。调试输出不要打到 stdout。学习执行路径，print 模式更干净。

## 4. 和全局 `pi` 的区别

| | 全局 `pi` | `./pi-test.sh` |
|---|---|---|
| 跑什么 | npm 装的编译产物 | 你正在看的 `.ts` |
| 断点 | 对不上源码行号 | 对上 `src/` |
| 改源码 | 必须 build | 保存后下次启动就是新代码 |

`which pi` 若是 `~/.pi/bin/pi`，那是安装目录，不是这份 checkout。

## 5. 常见卡住

**断点是灰色的、打不中**  
工作区根目录不是仓库根；或断点打在 `src/cli.ts` 却用了 `pi-test.sh`。改打 `main.ts` 或 `experimental/cli.ts`。

**`tsx: command not found`**  
用 `node_modules/.bin/tsx`，不要依赖全局 tsx。

**一启动就进 TUI，单步很痛**  
改用 `--help` 或 `-p --no-session`。

**想看 HTTP 请求**  
先把路径跟到 `packages/ai` 的 `streamSimple` 再下断点，不要从入口一路 F11。
