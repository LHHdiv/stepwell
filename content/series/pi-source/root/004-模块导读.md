路径：仓库根 `/`（本课文件夹对应源码不在 `packages/` 里）  
这些文件**不进运行时循环**。进程一旦从 `cli.ts` / `experimental/cli.ts` 走进 `main.ts`，就不会再回头读 `package.json` 的 scripts、也不会再执行 `test.sh`。

它们是另一条链：**人怎么进仓库、机器怎么构建、CI 怎么把关、维护者怎么发版。**

## 这些文件不进运行时，但决定运行时从哪来

```text
开发者本机
  README / AGENTS.md / CONTRIBUTING.md     规范：怎么改、怎么提
  package.json workspaces + scripts        合同：装什么、建什么、查什么
  tsconfig*.json / vitest.base.ts / biome  编译与测试如何看见源码
  ./pi-test.sh                             源码入口（tsx → experimental/cli.ts）
  ./scripts/auto-pi.sh                     构建产物入口（dist/bundle/cli.js）
  ./test.sh → npm test                     隔离 HOME 后跑测试

CI (.github/workflows/ci.yml)
  npm ci --ignore-scripts
  npm run build                            按包顺序编译
  npm run check                            一串 scripts/check-*.mjs
  npm test                                 不隔离 HOME（runner 本身已干净）

发版
  scripts/release.mjs                      bump + changelog + tag
  tag 推上去 → build-binaries.yml
    create-source-archive.sh
    build-binaries.sh                      Bun 编译独立可执行文件
  scripts/publish.mjs                      npm publish --provenance
  publish-release-announcement.mjs         等 registry 齐了再改 R2 latest 指针
```

根目录文件是这条链的**开关面板**。`packages/*/src` 才是面板后面的机器。

## 失败会怎样（先建立直觉）

| 失败点 | 谁先死 | 用户看不看得到 |
|---|---|---|
| `npm run check` 红 | husky pre-commit 拒提交；CI `Check` 步失败 | 看不到，包发不出去 |
| `./test.sh` 红 | 维护者发版脚本 `release.mjs` 停；PR 的 CI `npm test` 也可能红 | 看不到 |
| shrinkwrap / install-lock 过期 | `check` 里 `--check` 模式 exit 1 | npm 用户可能装到漂移的传递依赖 |
| `pi-test.sh` 找不到 tsx | 源码入口根本起不来 | 开发者立刻看到 |
| 运行时 `main.ts` 崩 | 与本模块无关 | 用户看到 |

本模块的失败几乎全是**把坏包挡在仓库里**。运行时失败要到 coding-agent 课才出现。
