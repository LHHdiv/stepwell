路径：`packages/chord/`  
npm 名：`@earendil-works/chord`  
版本：与 Pi 锁在一起（`0.85.1`）

## 这个包是什么

**应用组合运行时。** 它提供 facet（插件单元）、service（单例/多实例服务）、replicated state（权威状态复制）、以及可插拔的远程服务边界。开发在 Pi 单仓里，但它**不是 Pi 包**：

- `package.json` 的 runtime 依赖只有 `esbuild`（bundler 用）
- 源码禁止 `import` 任何 `@earendil-works/pi-*` 或 `packages/` 下其它目录
- 词汇是应用中性的：Facet / Service / Context / JsonValue，没有 Session、Agent、TUI、model、tool

其它 Pi 包可以依赖 Chord；Chord 不能依赖它们。箭头只能朝上：

```text
@earendil-works/chord
        ↑
Pi agent / protocol / server / client / coding-agent / 未来桌面
```

`PLANNING.md` 把这条边界写成硬约束。`test/boundary.test.ts` 用自动化检查证明包内没有 Pi 导入。

## 现行普通 `pi` 交互主链默认不走 Chord

跟路径请先把这句话钉死：

```text
已安装的 `pi`  → coding-agent/src/cli.ts
./pi-test.sh     → coding-agent/src/experimental/cli.ts
                    若 PI_EXPERIMENTAL 未开，或 argv 不是 server/client
                      → setupCli(); await main(args)
                           InteractiveMode / print / RPC
                             → packages/agent Agent.prompt
                             → agent-loop
```

这条链装配的是 `Agent` + 四个默认工具 + `pi-tui`。**不** `createFacetHost`，**不** `defineService`，**不**走 Chord 的远程绑定。

Chord 出现在两条旁路：

1. **coding-agent experimental 多进程。** `PI_EXPERIMENTAL=1` 且 `pi server` / `pi client` 时，`experimental/commands.ts` 截胡 `main`。session worker（`experimental/services/worker.ts`）用 `defineFacet` + `createFacetHost` 把 AgentController、Models、Transcript 焊成 facet 图；client-tui 再开一个 presentation 侧 host。进程之间的调用形状是 Chord 的 `ServiceCall` / `ServiceProviderUpdate`，外面包 Pi 自己的 socket / 路由。
2. **未来桌面。** 桌面学习伴侣会有 worker、TUI、WebUI 多环境。同一功能拆成多个 facet entry，各自加载进各自进程。Chord 提供「声明服务、绑定、复制状态、热替换」的通用机器；桌面产品自己写适配器和 UI。现行 CLI 不是桌面，不要把 `TuiMainScreen` 当成 Chord 的消费者。

agent 的 harness（`packages/agent/src/harness/`）已经开始从 Chord 借 `Context` 和 `JsonValue`。那是类型和取消语义的复用，**不是**交互主链走了 facet host。`packages/agent/docs/plugins.md` 写得很清楚：传输中性的 facet-service 原语在 Chord，agent core 不导出服务运行时。

## 三块积木

读源码时始终对着这三块，不要被文件名冲散。

### Facet

一个 facet 是：

```ts
{ id: string, setup(env: FacetEnvironment): void }
```

`setup` **必须同步**。它只做声明：`provide` / `provideMany` / `use` / `observe` / `replicatedState` / `own` / `onActivate` / `onDeactivate`。声明结束后，host 校验整张依赖图、按拓扑激活（先 provider 后 consumer）、按反拓扑销毁。

一个「插件」可以拆成多个 facet，分别打进 worker / presentation 等 entry。Chord 不解释 entry 名字，那是宿主的约定。

### Service

服务是带稳定 `id` 的类型令牌：

- `local: true`：进程内任意 JS 对象，永不进远程目录
- 默认远程可暴露：成员只能是「尾参为 `Context` 的 async 方法」或 `ReplicatedState`
- 模式：`singleton`（一个 provider，多个 consumer）或 `keyed`（一个集合 owner，动态实例）

`use(token)` 返回的是 **稳定 facade**，不是实现对象本身。provider 断开或被 `reload` 替换时，对象身份不变，下一跳才切到新实现。这是热替换能不断开消费者的原因。

### Replicated state

权威单写者、最新值复制。生产者改 `state` 代理，再 `publish(context)`。Chord 每次 publish flush 一批 decoded `Op[]`。远程每条订阅流有自己的 path codec。副本在 hydrate 之前 `value === undefined`；断线、替换、序号缺口会清就绪，直到下一次完整快照。

Delta 原语独立出口 `@earendil-works/chord/delta`。replicated state 用它，但不把 encoder 暴露给 facet 作者。

## 源码怎么分层

```text
facet loader / bundler          node/  bundler.ts
        ↓
facet host、生命周期、依赖图     facets/host.ts  loader.ts  api.ts
        ↓
service token、provider、facade  services/provider.ts  consumer.ts  handle.ts
        ↓
replicated state + 订阅         services/state.ts  state-codec.ts
        ↓
wire 语法（还不是对称 RPC）     services/wire.ts  loopback.ts
        ↓
strict JSON、Context            json.ts  types.ts  context/
```

`PLANNING.md` 里的对称 RPC peer（`rpc/peer.ts`）**还没落地**。现在远程边界是 `RemoteServiceTransport`：宿主自己提供 `invoke` / `subscribe`。Pi 的 protocol / server / client 就是这种适配器。loopback transport 让同进程的远程可暴露服务走和跨进程一样的语义。

## 和 coding-agent / 桌面的边界

| 问题 | 在哪回答 |
|---|---|
| 交互模式怎么画终端 | `packages/tui`，不经 Chord |
| Agent 循环怎么跑 | `packages/agent` `agent-loop.ts` |
| 实验 server 如何组 facet | coding-agent `experimental/services/worker.ts` |
| 实验 client TUI 如何订服务 | coding-agent `experimental/client-tui.ts` |
| socket 怎么帧、怎么鉴权 | `packages/protocol` / `server` / `client` |
| 插件怎么打包加载 | 本包 `bundler` + `node`；发现、安装、签名是宿主的事 |
| 桌面多窗口怎么拆进程 | 未来宿主；Chord 只提供 facet/service 机器 |

读本包时把 `RemoteServiceTransport` 当「一个能 invoke 和 subscribe 的适配器」。Pi 的信封怎么包，下一包再打开。
