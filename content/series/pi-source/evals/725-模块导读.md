路径：`packages/evals/`  
npm 名：`@earendil-works/pi-evals`  
`private: true`，不发布。版本号仍跟仓库锁在 `0.85.1`。

## 这个包是什么

用真 `AgentSession` + 真模型，做 **行为评测**，不是 vitest 单元测试。它把 Pi 的会话适配成 [vitest-evals](https://github.com/getsentry/vitest-evals) 的 Harness：隔离的临时项目目录、关掉（或白名单）工具、跑 prompt、把 JSONL 会话当 artifact 留下来。

测的是：

| 文件 | 测什么 |
|---|---|
| `smoke.eval.ts` | 最瘦路径：无工具，首都问题，检查 usage 字段 |
| `docs.eval.ts` | 文档页 vs 实现：模型读 docs + grep 源码，提交 match/mismatch |
| `extensions.eval.ts` | 系统提示里的扩展写作指南是否真能让模型写出可加载的 hello 扩展（对比实验） |

`test/*.test.ts` 是评测脚手架自己的单元测试（不打电话），`npm test` 走 `vitest.test.config.ts`。评测走 `npm run eval` → `scripts/run-evals.mjs` → `vitest.config.ts`（只 include `src/**/*.eval.ts`）。

## 在执行链的哪一段

现行 `./pi-test.sh` 交互 / print **不跑** 本包。

evals **会**走 coding-agent 主装配链，和 print 模式同一套焊点：

```text
npm run eval -- --provider openai --model ...
  scripts/run-evals.mjs
    vitest run --config vitest.config.ts
      createPiCodingAgentHarness
        ModelRuntime.create()
        createAgentSessionServices({ cwd: tmp/workspace, agentDir: tmp/agent })
        SessionManager.create(...)
        createAgentSessionFromServices   【与 CLI 相同】
        session.prompt(input)
          Agent.prompt → agent-loop → streamFn → pi-ai
```

不走 TUI，不走 experimental server/client，不走 sqlite-node。会话是 coding-agent 的 JSONL `SessionManager`。

仓库根 `package.json` 有 `"eval": "npm run eval --workspace=@earendil-works/pi-evals --"`。

## 依赖谁

devDependencies：`pi-ai`、`pi-coding-agent`、`vitest`、`vitest-evals`。没有 `pi-protocol` / `pi-server`。

认证走正常 `ModelRuntime`：环境变量 API key、Pi 订阅、本机 `~/.pi/agent` 的 auth（注意 eval 的 `agentDir` 是临时目录，**认证仍来自 ModelRuntime.create() 的默认路径**，不是临时 agentDir 里那份空文件）。

## 怎么跑

```bash
# 仓库根，必须成对给厂家和模型
npm run eval -- --provider openai --model gpt-5.6-sol

# 等价环境变量（CLI 优先）
PI_PROVIDER=openai PI_MODEL=gpt-5.6-sol npm run eval

# 只跑一个文件 / 一条测试
npm run eval -- src/extensions.eval.ts
npm run eval -- -t "creates, reloads, and uses"
```

其余 argv 原样给 vitest。stderr 会打 `artifacts=` 指向本次 `.eval/<timestamp>_<uuid>/`。`runs.jsonl` 索引每次 harness run 和 `sessions/` 下的 JSONL。这些文件可能含 prompt、代码、工具输出，勿提交（`.eval/` 应被 ignore）。

没有默认模型且 harness 自己也没写 `model:` 时，runner 允许 `default-model=none`，但当前三份 eval 都依赖 runner 默认（extensions/docs/smoke 没写死模型），所以实际上必须提供一对。
