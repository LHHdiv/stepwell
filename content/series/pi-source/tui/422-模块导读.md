## 覆盖原先那份浅导读

旧课只说：执行链到 InteractiveMode 才大量 import 这里；print 模式（`-p`）几乎不碰；本包不知道模型、工具、会话；coding-agent 的 `modes/interactive/` 把 Agent 事件变成组件 props；第一份会是 `tui.ts` 的 `start`/`stop`。

这些仍然成立。本目录把那一句话拆成按**渲染管线**排序的文件课：从 `TuiBase.start/stop` 进终端，经差量写屏，到 layout 树，再到组件，最后到 Editor。

## 这个包是什么

终端差量渲染库。把组件树画到 stdout，处理键盘和（全屏时）鼠标。它**不** import `@earendil-works/chord`，也**不**知道 Agent。依赖只有 `get-east-asian-width` 和 `marked`。

coding-agent 入口：

```text
InteractiveMode.run
  createInteractiveTui()                    modes/interactive/tui-renderer.ts
    new ProcessTerminal()
    tuiMode === "fullscreen"
      ? new TuiAltScreen(terminal, ...)
      : new TuiMainScreen(terminal, ...)
  tui.addChild(transcript / editor / ...)
  tui.setFocus(editor)
  tui.start()
```

启动选择器、config selector 也 `new TuiMainScreen(new ProcessTerminal())`。实验 client-tui / mini tui 同样只把本包当画布。

## 渲染管线（文章按这条排）

```text
tui.start()
  beforeTerminalStart()                    AltScreen：进 1049h、开鼠标
  terminal.start(onInput, onResize)        raw 模式、Kitty 协商、StdinBuffer
  afterTerminalStart()
  requestRender() → schedule ≤16ms → doRender()

TuiMainScreen.doRender
  this.render(width)                       Container 把 children 的行拼起来
  compositeOverlays
  和 previousLines 比，只写脏行 + CSI 2026

TuiAltScreen.doRender
  renderLayoutFrame(layoutRoot)            layout.ts：vstack/hstack/scroll
  选区 / 搜索高亮 / 滚动条 / flash
  按行差量写进固定视口
```

输入反向走：

```text
stdin → StdinBuffer 拆完整序列
  → ProcessTerminal 规范化 Shift+Enter
  → TuiBase.handleTerminalInput
       全局 listener（AltScreen 视口键、Ctrl+C）
       focused.handleInput                 通常是 Editor
  → requestImmediateRender                 键盘不走 16ms 节流
```

## 两套屏幕

| | `TuiMainScreen` | `TuiAltScreen` |
|---|---|---|
| `mode` | `"regular"` | `"fullscreen"` |
| 缓冲 | 主屏 + 滚动历史 | 备用屏 1049h，应用自己滚 |
| 停掉时 | 光标移到内容末尾换行 | 退回主屏，把完整文档打印出来 |
| 鼠标 | 无（overlay 点击靠组件自己，但终端未开鼠标协议） | SGR 鼠标、选区、滚动条 |
| 布局 | 只有垂直 Container | 可选 `setLayoutRoot` 走 layout 树 |

现行交互默认随设置在两者间切换。print 模式不构造它们。

## 组件契约

每个可见块实现 `Component`：

- `render(width): string[]` — 一行一个字符串，可含 ANSI
- `invalidate()` — 清缓存（主题切换）
- 可选 `handleInput` / `handleMouse` / `wantsKeyRelease`

可聚焦的还实现 `Focusable.focused`。聚焦时在光标处插入 `CURSOR_MARKER`（`ESC _pi:c BEL`，零宽 APC）。TUI 找到、剥掉、把硬件光标放过去，IME 候选框才跟得上。

## 和 Chord / Agent 的边界

本包不依赖 Chord。实验多进程的 presentation 侧会 `createFacetHost` 再 **另外** 开一个 TuiAltScreen——facet 提供 slash command / models 状态，TUI 仍然只吃 props。未来桌面若用本包画终端面板，也是同一边界：Chord 管服务，TUI 管单元格。
